# 锁屏后继续使用（Locked use）

2026-11-16，主人裁决：在 macOS 上加「锁屏后让 AI 继续使用这台电脑」。电脑已经锁屏时，正在这台电脑上
运行的 Agent 任务需要用屏幕，Cindy 先用隐私屏盖住所有显示器，再用主人事先保存的登录密码临时解锁；
AI 在隐私屏后面工作，用完或有人碰电脑就重新锁屏。第一期只做 macOS 本机闭环。

给用户的一句话：**电脑锁屏后，你从手机发的任务也能继续用这台电脑；屏幕始终被隐私屏盖着，用完自动重新锁上，
有人碰一下就立刻锁屏。**

这是一条新的权限边界：[隐私屏](privacy-screen.md)本身不解锁、不保存密码，这两件事只在本文描述的范围内发生，
其他功能不得借用这里保存的密码或解锁能力。

## 和隐私屏的关系

| | 隐私屏（用隐私屏代替锁屏） | 锁屏后继续使用 |
| --- | --- | --- |
| 起点 | 电脑没锁 | 电脑已经锁屏 |
| 做什么 | 不让电脑锁，改用遮罩挡住 | 先盖遮罩，再临时解锁 |
| 结束 | 有人碰电脑才锁 | 任务用完、有人碰电脑、遮罩出问题都锁 |
| 保存密码 | 否 | 是，只在本机，由签名助手读取 |

两者共用同一个隐私屏：同一种画面、同一个物理输入拦截、同一套“锁不上时”的兜底。两个开关互相独立：
只开「锁屏后继续使用」也能用，结束时一律还原为锁屏，不看「用隐私屏代替锁屏」开没开——电脑原本就是锁着的，
用完就还回锁着。

## 流程

1. Agent 任务调用电脑工具（截图、读窗口、点按、输入），宿主发现屏幕已锁。
2. 宿主检查能否解锁（见「谁能触发解锁」），不满足就照旧返回 `screen_locked`，并告诉 Agent 原因。
3. 先盖上隐私屏：遮罩在锁屏界面下面铺好，物理输入拦截同时开始。遮罩没盖好就不解锁。
4. 签名助手唤醒屏幕，把保存的密码填进系统锁屏界面的密码框，按下确认；成功只认系统报告的解锁状态。
5. 隐私屏文字显示「Cindy 正在锁屏后使用这台电脑」，第二行写「碰一下就会立刻锁屏」。AI 在后面照常工作。
6. 以下任一情况立即真锁屏：
   - 发起解锁的任务都已停止运行，或 2 分钟内没再调用电脑工具；
   - 有人碰电脑（判定与隐私屏相同：按键、鼠标按下、按下修饰键、一秒内滚动 30 点以上）；
   - 遮罩或输入拦截失败、新接了显示器；
   - 主人在设置里关掉这项功能；
   - Cindy 或助手退出（助手退出本来就会锁屏）。
7. 因为有人碰电脑而锁屏后，**暂停自动解锁**，直到主人自己解锁一次。同一个人反复碰电脑，Cindy 不会和他抢。
8. 锁屏失败时沿用隐私屏的「锁不上时」：遮罩不撤，提示其他锁屏方法，主人用系统身份验证撤下。

在第 3、4 步之间如果有人碰了锁屏界面，取消这次解锁并暂停；万一解锁已经完成，立刻重新锁屏。

结束时只认系统报告的锁定状态：撤遮罩后系统仍没锁，就直接再锁一次。2026-11-16 首次实机测试出过事故：
隐私屏原有「盖上后系统被解锁过，就当主人回来了，撤遮罩不锁屏」的处理（#10665），把 Cindy 自己的
这次解锁也当成了主人回来，任务结束时撤掉遮罩却没锁屏，桌面开着约 3 分钟，由主人发现。现在锁屏后使用
盖的遮罩不走这条处理，结束一律真锁屏，并在之后再核对一次锁定状态。

## 谁能触发解锁

只由宿主在 Agent 任务调用电脑工具时触发。它不是模型可以调用的工具，不进渲染进程 IPC，也不进 device-link
远程调用白名单；遥控端和插件都没有入口。

同时满足才解锁：

- 这台电脑开了「锁屏后让 AI 继续使用这台电脑」，并且保存的密码还在。
- 调用来自这台电脑上的 Agent 任务：插件经宿主直接调用电脑工具（没有任务）不算。
- 这个任务在本机任务库里、不是远程宿主上的任务，并且此刻正在这台电脑上运行。供应商分享、供应商组的外部
  使用方的任务不在本机任务库里，因此不会触发。
- 这个任务没有在共享给访客（[共享任务](shared-task-mode.md)）。
- 这一轮如果来自 IM 渠道，触发它的必须是主人本人（沿用渠道轮次登记的 `requesterIsOwner`，与伙伴技能读写同一判定）。
- 没有处于「有人碰过、等主人手动解锁」的暂停中，也不在失败后的冷却期内。
- 没有远程桌面或屏幕查看连接（含只看不控和插件画面），也没有 macOS 屏幕共享连接。

「IM 轮次必须是主人触发」对所有 IM 与 hook 渠道都生效：每一轮都登记触发者，渠道没有给出主人身份
证明的一律按不是主人处理（2026-11-16 安全审阅：此前只有带直通工具作用域的渠道登记，其余渠道放行）。

## 解锁期间只有锁屏后继续使用能用这台电脑

2026-11-16 主人要求：锁屏后继续使用打开电脑期间，除了它自己（发起解锁的任务，以及同样有资格触发解锁的
任务），谁都不能不经密码进入。因此：

- 其他任务（没有资格触发解锁的）和插件经宿主的电脑工具调用一律拒绝（`LOCKED_USE_BUSY`），不送达驱动。
- 远程桌面或屏幕查看一连上，立即真锁屏；连接还在时不解锁。远程端要进入，走它自己的解锁（输密码或
  Face ID 自动解锁）。
- macOS 屏幕共享有连接时同样处理：隐私屏不进入屏幕采集，屏幕共享看到的是遮罩后面已解锁的桌面。
  其他远程控制软件（TeamViewer、向日葵等）无法可靠识别，**不在保护范围内**，开着这类软件时不要开启本功能。
- 任何应用打开了安全键盘输入（终端的「安全键盘输入」、聚焦的密码框、密码管理器等），隐私屏的输入拦截
  就看不到按键，电脑前的人可能隔着遮罩打字；这时立即真锁屏。每秒检查一次，读不到时按已打开处理。
- 有人碰电脑、遮罩出问题、任务用完：真锁屏（见「流程」）。

已知余量：安全键盘输入每秒检查一次，打开后的这一秒内按键可能漏过拦截。同一用户身份下运行的其他程序
不在防护范围内：它们本来就能操作这台电脑上的一切。

这是主人在 2026-11-16 认可的方案落地时的具体口径：原方案写的是“主人本人消息和主人建的定时任务”。实现时不读
消息来源字段做判断——[消息来源](message-source.md)规定那些字段只用于归属展示、不是权限判据。改用宿主现有的、
本来就用于授权的事实：任务是否在本机运行、是否共享给访客、IM 轮次是不是主人触发。结果是：

- 主人的普通任务、主人从手机发的消息、定时任务（包括 Webhook 触发的定时任务：事件正文不进任务，只是门铃，
  任务内容由主人自己写）、伙伴任务、插件或其他任务转来的消息，都能触发；这些本来就能在没锁的电脑上使用电脑工具，
  与[伙伴授权](teammate-authority.md)「不设伙伴专属权限门」一致。
- IM 里别人的消息、共享任务访客、远程使用这台电脑模型的其他账号，不能触发。

## 保存密码

- 开启时由原生签名助手弹出 macOS 的密码框（不是网页），主人输入本机登录密码；助手先用系统接口验证一次，正确才保存。
- 密码存进登录钥匙串，条目只允许这个签名助手读取，不经过 JavaScript、日志、模型、遥控端或任何网络。钥匙串
  命名空间与远程解锁分开，两边互不读取。
- 不加 Touch ID 保护：解锁时没人在电脑前，无法按指纹。
- 解锁前先用系统接口验证保存的密码；验证不过（主人改过系统密码）就删掉保存的密码，功能显示为需要重新设置，
  不往锁屏界面填错误密码，避免把账户锁住。
- 关闭功能会删除保存的密码。
- 登录钥匙串如果被设成锁屏时自动锁定，读不到密码，这次解锁失败；Cindy 不去改钥匙串设置。
- 不随账号同步，不进入迁移助理，不进入跨电脑设置复制。

风险与取舍（主人知情选择）：电脑上存在一份可还原的登录密码。能读出它的只有这个签名助手；但同一用户身份下的恶意
程序如果攻破助手或冒充 Cindy 主进程，可能拿到它。另一种做法是装 Apple 授权插件、只持有解锁权（Codex 的做法），
需要管理员安装、改系统授权规则，插件出错可能影响正常登录，暂不采用；两种做法放在同一个解锁接口后面，以后可替换。

## 权限

- 签名助手要有「辅助功能」权限才能操作锁屏界面的密码框。开启时如果没有，提示主人去
  「系统设置 → 隐私与安全性 → 辅助功能」允许；允许前不会解锁。
- 隐私屏的输入助手同样需要辅助功能权限（与隐私屏相同）。

## 设置

设置 → 通用 → 离开电脑时，「用隐私屏代替锁屏」之后：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 锁屏后让 AI 继续使用这台电脑 | 关 | 电脑锁屏后，正在运行的任务需要用屏幕时，Cindy 先盖上隐私屏，再用你保存的登录密码临时解锁；用完或有人碰电脑就重新锁屏。密码只加密保存在这台电脑上。 |

- 打开时弹出系统密码框；取消或密码不对，开关保持关闭。
- 处于暂停时在说明下显示「有人碰过电脑，已暂停。你解锁一次后恢复。」
- 保存的密码失效时显示「登录密码已更改，请重新打开这项设置。」并把开关显示为关。
- 只在 macOS 14 及以上显示（与隐私屏相同）。

## 告诉 Agent 什么

电脑锁屏、这次又不能解锁时，电脑工具返回的 `screen_locked` 提示带上原因，Agent 据此告诉主人，不循环重试：

- 功能没开：主人可以在「设置 → 通用 → 离开电脑时」打开「锁屏后让 AI 继续使用这台电脑」。
- 暂停中：有人碰过电脑，需要主人解锁一次。
- 需要重新设置：登录密码已更改。
- 这个任务不能触发：说明是任务来源不允许，不细说原因。
- 解锁失败：稍后再试或请主人解锁。
- 有远程连接：远程桌面或屏幕共享连着时不解锁，主人可以从那条连接自己解锁。
- 正被别的任务使用：工具返回 `LOCKED_USE_BUSY`，告诉主人这一步需要电脑解锁。

## 不支持的情况

合盖且没接外接显示器、电脑睡眠、重启后还没登录过（FileVault）、切换到了别的系统用户、锁屏界面出现恢复或
选择用户等未识别界面（助手一律不填）。这些情况照旧提示主人。Windows、Linux 暂不支持。

## 待验证

以下需要在真机锁屏状态下验证，验证前不能当作已确认：

- 锁屏状态下能否先建好遮罩窗口和输入拦截，解锁瞬间不露出桌面。
- 在锁屏界面上按键或点按时，输入拦截是否会吞掉主人的第一下输入（预期：吞掉后锁屏确认、拦截退出，主人可以正常输入）。
- 熄屏、多显示器下的解锁成功率。
