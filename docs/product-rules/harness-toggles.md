# Harness 开关：这台电脑提供哪些 Harness

> **读取时机**：新增或修改 Harness 开关、它的存储与下发，新增一个 Harness，或新增任何
> 「列出可选引擎 / 模型」的入口之前

## 1. 定位

Cindy 同时承载多个 Harness（目前 Claude Code、Codex、Pi，以后还会增加）。用户不用的
Harness 不应该一直出现在模型选择器里。开关让用户在这台电脑上关掉某个 Harness，关掉后它不再
作为新的选择出现（2026-11-14 维护者裁决：按电脑保存）。

## 2. 两个清单

- **已注册**：`maker.listAvailableAgents()`。负责执行、恢复与 `requireAgent`。开关不碰它。
- **可选** = 已注册 − 用户在这台电脑上关掉的。负责一切「新的选择」。

关掉一个 Harness 不打断正在运行的任务，历史任务照常打开、继续；已有任务里当前的引擎始终
留在它自己的模型选择器里，只是不能再切到其他被关掉的引擎。

## 3. 规则

- **按电脑保存**：`<userData>/harness-preferences.json`，不随账号。手机、远程控制端看到的是
  运行 Agent 的那台电脑的设置，经 `maker:list-available-agents` 与 `maker:agents:changed`
  原有链路下发，不新增跨端协议。
- **只记关掉的**：没有记录就是开着。以后新增的 Harness 默认开着，不需要迁移；本版本还不认识的
  id 原样保留，不丢用户的选择。
- **至少保留一个**：不能关掉最后一个开着且已注册的 Harness。没装好的 Harness（例如 Pi）可以
  预先关掉。即使手改文件关掉了全部，可选清单也会退回全部已注册的引擎，不会一个都选不了。
- **入口**：设置 →「关于」每行 Harness 的版本菜单里的「在模型选择器中显示」；Agent 通过设置工具的
  `harnesses` 分类（`list_app_settings` / `update_app_settings`）修改同一份设置。

## 4. 哪些入口读「可选」

选择入口（读可选）：
- 桌面模型选择器、新任务草稿（关掉当前草稿引擎时自动退回第一个可选引擎）、伙伴和定时任务的模型选择
  （以上经 `useAvailableAgents`）
- 手机新建任务，以及已有任务的「切换引擎」
- 远程控制端，以及其他电脑借用本机 Agent 时看到的目录
- IM `/model` 卡（`hook-control` 的 `listAgentModels`）
- 普通任务默认模型候选（`appDefaultModelControl`）、伙伴默认模型链的推导
- 插件模型选择器、插件读取的可选模型、插件任务设置
- 外部应用连接本地 Agent 时的模型清单
- Orca `list_available_models` 在本机且未指定引擎时
- 帮助与摘要兜底：开着的优先，都不可用时才退回关掉的

执行入口（读已注册，保持不变）：已有任务的运行与恢复、远程分配与组内切换、辅助模型调用、
Agent 从已有任务继承引擎创建新任务（`sessionExecutionSelection`）。

新增一个列出引擎或模型的入口时，先判断它是「新的选择」还是「执行已有选择」，再决定读哪个清单。

## 5. 已知边界

- IM 连接时声明的 `agents` 仍是已注册清单（连接时一次性发送）；只有 `/model` 卡按可选清单实时过滤。
  IM 里已绑定在被关掉 Harness 上的会话，`/model` 卡不再列出该 Harness 的模型。
- Orca 查询其他电脑的模型（`agentDeviceId`）时沿用那台电脑的目录，暂不扣除那台电脑的开关。
- 编辑一个已在被关掉 Harness 上的定时任务时，表单会提示模型不可用；任务本身照常按时运行。
- 关掉的 Harness 仍按原流程检查和安装更新。引擎本来就按需初始化，没有可省的预热；跳过更新
  涉及应用更新链路，需另行与维护者确认后再做。
